# GitHub 协作 · 共用 dev

每个人在自己电脑的本地 dev 开发，共同推送 GitHub 的 dev。不需要任务分支或 PR。

## 日常操作

1. 打开项目，当前不在 dev 时，确认旧分支工作已保存后点击「切换到 dev」。旧分支保留，不会自动带入其中独有代码；有改动先请 DSH 协助保存，必要时显式迁移旧任务成果。
2. 上班点击「从 dev 拉取」，开发、自测。
3. 查看文件清单和差异，在「提交并推送」填写提交说明，确认改动后推送到共用 dev。插件暂存全部改动（含未跟踪文件），创建提交后 fetch 最新 dev，并在隔离 worktree 中尝试合并；开发目录不承载冲突现场。快照变化会拦截，整合新代码后暂停推送，需审查再提交。
4. 推送完成后，到「远程部署」发布 dev，再打开 dev 网站在线测试。推送不会自动部署；本地部署入口已移除，不再要求启动本地 Vite/Spring Boot。
5. 本次隔离合并有冲突则保存受限的服务端冲突报告并清理临时 worktree，不把冲突标记或未合并索引写进开发目录，不推送。本次操作通知绑定的当前会话，解释共同基线、本地和最新远程的意图及解决方案；先征求你的确认，获准后才修改开发代码。修好并审查后，再点击推送时重新 fetch 并生成新的合并结果。插件不再展开冲突 diff；通知不授权修改、解决冲突或推送，开发者明确确认后再处理、自测、推送。会话正在执行时，通知排队到下一轮，不打断当前工作。遇到 Git hooks/签名等失败按提示处理，不强推，不自动选一边。

打开项目、刷新或重启不会重新展示或通知旧本地冲突；没有后台冲突轮询。仅本次拉取或推送的隔离合并冲突报告触发会话通知，同一报告不重复唤起会话；下次推送重新获取远程并重新合并。无当前会话或投递失败明确提示，不假称送达。报告仅存内存、绑定 canonical 仓库目录和本地 HEAD，宿主重启或本地 HEAD 改变后旧报告不可用。所选项目可以与会话初始工作目录不同。已有未完成本地 merge 的仓库会明确拦截推送；不会为了隐藏旧冲突自动 abort/reset，请自行确认后处理。

面板按「共用 dev 开发 → 本地部署与测试 → 提交并推送」排列，不再提供单独保存本地提交、运行构建与后端测试、确认页面自测三个按钮。推送不运行构建和后端测试，不要求插件的部署验证记录或服务仍在运行；人工页面自测在推送时确认。「从 dev 拉取」也采用临时隔离合并，支持未提交修改：用临时索引生成本地快照，不先提交、不自动 stash。冲突只生成报告并通知会话，开发目录不写冲突现场。拉取按实际内容逐层整合本地暂存和工作区修改，不再仅因修改同一文件而暂停：相同内容直接同步，同文件不同位置的兼容修改自动合并；真正不兼容才生成隔离冲突报告。临时快照不进入 dev 提交历史，本地独有成果仍保留为待提交修改。特殊文件、不安全的路径状态及无法无损表达的 intent-to-add 索引会明确拒绝，不能保证安全时不会强行覆盖。写回前使用 Git 锁、指纹及逐文件核对，失败尝试恢复；发现外部并发修改时不擅自覆盖，明确提示人工恢复。它不是操作系统级原子事务，拉取期间仍不要同时让其他程序切换分支或修改仓库。已有未完成 Git 操作仍拦截，不自动 abort/reset。拉取后需重新部署、自测。推送若被同事的并发更新拒绝，本地提交保留，刷新并同步、重新启动验证后重试。

## 本地部署

当前针对团队 React/Vite + Maven/Spring Boot 项目：需要已安装 Node/npm、Maven 和项目要求的 Java（当前 Java 21+）；系统工具缺失提示人工安装，不静默使用系统包管理器。启动先检查 package.json 中直接依赖（含开发依赖）和 Vite 入口，缺少时自动安装：有 npm 锁文件用 `npm ci --include=dev --no-audit --no-fund`，没有则 `npm install --package-lock=false --include=dev --no-audit --no-fund`，不主动生成锁文件。安装失败时停止，不因 Git 分支、提交状态或源码变化拒绝启动；安装可随停止按钮取消。已存在但版本不匹配、间接依赖损坏目前不作完整自动修复。

依赖准备完成后直接启动 Vite 与 Spring Boot；Maven 启动时仍可能按 pom 编译 Java、解析下载后端依赖，这属于运行服务所需，不是额外测试。启动和推送均不自动执行额外的 `npm run build` 与 `mvn -f backend/pom.xml test`。需要完整构建/自动化测试时由开发者单独执行或交由团队 CI。启动成功只代表服务可运行，不代表完整测试通过；推送前应自行完成页面自测。推送保留 Git 快照、并发改动、隔离合并、冲突及不强推保护，但不再依赖运行环境或自动检查记录。安装可能联网、执行依赖生命周期脚本，npm ci 可能重建 node_modules；只对可信项目启动。安装进度与错误显示在本地运行日志中。

固定前端 5180、后端 8081，端口占用拒绝启动，不接管或停止已有服务；停止仅清理插件启动的进程。经用户明确授权，插件服务端暂时固定本机 MySQL（127.0.0.1:3306/xinglian，root 账号，密码内置但不在文档展示），仅向本地部署后端注入 XINGLIAN_DB_URL、XINGLIAN_DB_USERNAME、XINGLIAN_DB_PASSWORD；不读取项目 .env.local，不向前端、依赖安装、构建或测试传递应用数据库凭据，日志对固定密码脱敏。此为凭据不入源码规则的插件范围例外，固定密码会随插件分发。127.0.0.1 指运行 DSH 的电脑，其他开发者不会因此连接到同一台远程数据库。需自行准备 MySQL 及 xinglian 库，插件不建库、不重置账号或删除数据；后端可能建表并初始化演示数据。服务器部署配置和隔离 MySQL 自动化测试不变。首次启动前请确认项目配置。停止或插件重启后自测确认失效。日志限长且脱敏，但仍不应向测试环境注入生产秘密。

推送门禁只约束本插件，无法阻止成员直接使用其他 Git 工具推送；人工页面确认也不代表全业务已被自动验证。

## 安装与登录

通过 DSH 插件管理使用本地安装。不要修改应用归档或绕过 Agent 运行期间安装保护。后端修改需重载插件或重启 DSH，再刷新页面/重开「GitHub 协作」。

运行 DSH 的宿主电脑（不是浏览器所在电脑）需要 Git 和官方 GitHub CLI gh；本地部署另需 Node.js/npm、Maven、项目要求的 JDK 21+。Windows 和 macOS 都需将这些工具加入宿主 PATH，Java 可通过 JAVA_HOME 配置。Windows 点击「启动本地环境」时会检测并尝试自动补齐 Node.js/npm、Maven 和 JDK；macOS 仍需自行安装。Git 和官方 gh 仍需预先安装。

- **Windows**：安装 Git for Windows；GitHub CLI 可在 PowerShell/终端运行 `winget install --id GitHub.cli --exact`；本地启动会尝试自动安装缺少的 Node.js/npm、Apache Maven 和 JDK 21+，也可自行预装。面板「选择目录」使用 Windows 文件夹选择器，也可手动填写 `C:\\Users\\你的名字\\Projects\\XiAN-OA` 等绝对路径。路径指的是 DSH 宿主上的目录。
- **macOS**：安装 Git（例如 Xcode Command Line Tools）；GitHub CLI 可运行 `brew install gh`；另安装 Node.js/npm、Maven 和 JDK 21+。面板使用 macOS 文件夹选择器，也可手动填写 `/Users/你的名字/Projects/XiAN-OA`。
- **安装或更新工具后**：完全退出并重新启动 DSH，让宿主进程重新读取 PATH/JAVA_HOME，再刷新面板、检查登录状态。仅刷新浏览器、重开终端或点击面板刷新不能更新已运行宿主继承的环境变量。面板显示 `/status` 返回的宿主系统，不使用浏览器 navigator 判断系统。

本人在官方授权页面输入验证码，不共享验证码或 Token。凭据由 gh 保存，系统凭据存储不可用时可能回落到明文配置；退出影响其他使用同一 gh 账号的工具。仅 github.com。

### Windows 首次本地启动自动补齐工具

- 仅「启动本地环境」触发安装；状态刷新/检查不会安装系统工具，macOS 不变。先检查项目与端口，随后检测现有工具，只安装缺少项。
- Node.js/npm：固定 `winget install --id OpenJS.NodeJS.LTS --exact --source winget`；JDK：固定 `EclipseAdoptium.Temurin.21.JDK`，检测要求完整 JDK（java、javac 和版本文件），最低 21。winget 不可用时明确提示安装/修复 App Installer，不执行第三方引导脚本。
- Maven：官方 Apache Maven **3.9.11** HTTPS 归档，内置 SHA-512 校验通过后解压至 `%LOCALAPPDATA%\DeepSeekHarness\tools`，不依赖不存在的 Apache.Maven winget 包。
- 安装日志显示在部署日志中；单个工具安装最多等待 30 分钟，可点击停止取消插件持有的安装进程树。系统安装器若已移交系统服务，取消不保证回滚已安装内容。正常 UAC 授权需本人操作，不绕过权限。失败会停止后续启动，提示网络/权限/安装状态，不循环安装。
- 安装后仅重新检测一次，检测常规安装目录以适应 DSH 旧 PATH，在私有子进程环境中补齐 PATH/JAVA_HOME 后继续准备项目依赖和启动；不永久修改系统环境。非常规工具路径仍需手动配置。取消 Maven 解压可能留下临时目录，不会把半解压目录作为正式安装使用。
- 仍需在 Windows 实机验证首次安装、UAC、代理网络、停止/重试和启动；自动化测试使用模拟安装器，不代表实机安装成功。代理须对 DSH 宿主生效，浏览器能访问不代表 winget/PowerShell 可联网。

### 安全边界与特殊路径

- Windows 的 Maven 等批处理工具支持空格、中文和括号路径；为避免 CMD 展开/注入，批处理工具路径与参数中的引号、`%`、`!`、`&`、`|`、`<`、`>`、`^` 等会被拒绝。建议系统工具安装在常规路径。
- Windows 本地部署使用盘符目录；CMD 批处理不支持 UNC 项目工作目录，插件会明确拒绝，不会悄悄在其他目录启动。
- 停止服务只针对插件持有的活动进程 PID 及其进程树，不按进程名或端口误杀。若 Windows 启动器已经异常退出，无法安全确认其后代是否残留；面板会提示清理未确认，需检查运行日志及端口，不保证异常孤儿进程全部自动回收。
- Git 路径会检查大小写/Unicode 冲突及 Windows 保留名、ADS 等别名。分层拉取支持 Git 内建 LF/CRLF 转换；不能无损往返的混合换行、特殊编码/ident 转换或同步中修改属性规则时会安全拒绝，保留本地文件供人工处理。

API 限本机回环，校验 Host/Origin、JSON、CSRF；不把访问 Token 发给浏览器。

## 插件远程更新

插件独立发布仓库为 `liudaozhi01/dsh-simple-github`（私有），与业务仓库分开。使用者的宿主 gh 登录账号需有该私有仓库读取权限；不共享 Token，也不在插件里嵌入密钥。

1. 打开协作面板时自动检查一次插件更新，显示当前版本、远程正式版本及发布说明；也可在底部点击「检查插件更新」重新检查。不会后台轮询或自动安装；若有上次安装结果待核对，优先显示该结果，不自动检查覆盖提示。
2. 有新版本时点击「更新插件（自动安装）」。先等待所有相关 Agent 任务结束、停止插件本地部署、避免启动新任务或其他插件操作，再确认更新。确认是操作员承诺，不是宿主原子忙闲锁；宿主热加载会核对整个 profile，不能保证其他未加载改动完全不受影响。
3. 下载到 **DSH 宿主**私有临时目录。检查凭据 15 分钟有效；下载前重新核对 Release，限制 16MiB，并校验 GitHub 资产 SHA-256 和大小。不匹配则拒绝。下载完成后由客户端调用官方 remote.pluginManager.inspect/installBundle，安装请求不依赖将被卸载的插件 HTTP handler；不先卸载自己、不自动批准构建脚本、不绕过兼容检查、不修改应用归档。
4. 宿主返回 applied 时提示已应用、重新打开面板确认版本；restart-required 时提示手动重启 DSH。不会自动重启。面板重载后通过当前标签页 sessionStorage 的 requestId 与 waitForInstall 核对结果；返回 null 或通信异常均显示未知，不自动重试。出现未知请通过插件管理确认版本；不要重复安装。旧客户端没有自动安装桥接时保留手动路径提示。

首次启用此功能需先手动安装 `0.2.0` 或更新版本；旧 `0.1.0` 没有检查更新入口。下载路径属于宿主（远程浏览器不能直接当作本地路径使用），临时目录可能被系统清理；用完后可人工删除。安装执行的是可信插件代码，SHA-256 只校验下载完整性，不替代发布者信任或宿主兼容性检查。检查失败需检查网络、gh 登录和仓库权限；不绕过权限，不自动重复安装。

# GitHub 协作本机网页版

在现有插件目录运行 `node web/launch.js`，然后在同一台电脑打开 [http://127.0.0.1:8787/](http://127.0.0.1:8787/)。端口占用时可以运行 `node web/launch.js 8788`，浏览器地址按终端输出为准。完成操作后，在终端按 Ctrl+C 关停。

需要 Node.js 22、Git 和 GitHub CLI（`gh`）。可以用页面的 GitHub 设备授权登录，也可以复用本机 `gh` 的登录状态。在「项目」页填写 Git 仓库根目录的绝对路径，点「打开项目」。macOS 和 Windows 也可以点「选择目录」。

默认项目为 `ssal-team/XiAN-OA`，协作分支为 `dev`。原 GitHub 管理员登录后，可在「设置 → GitHub 管理后台」编辑仓库、协作分支和克隆设置。协作分支用于日常拉取和推送，克隆分支仅影响单分支新克隆。保存后重新启动 Web 服务。已有仓库的 origin 和当前分支由成员自行核对。

设置保存到网页版的 `web/github-project.local.json`。使用 `SIMPLE_GITHUB_WEB_CONFIG` 启动时，设置保存到该变量指定的文件。打包会使用相同的配置选择规则生成团队默认值。提交、推送和源码恢复仍受原有确认流程、GitHub 写权限及分支保护约束。

本入口仅监听 `127.0.0.1`。可打开或克隆项目、查看差异、同步、提交并推送、恢复历史源码。网页版在设置中提供远程更新。

XiAN-OA 的 dev / test 发布通过系统 OpenSSH 直连原有受控发布入口。打开「设置 → 发布服务器连接」，填写自己的 SSH 用户名和私钥路径，也可以用「查找本机私钥」选择。点击「保存并测试连接」后，程序会校验固定的服务器 ED25519 指纹并只读检查发布入口。

命令行也可配置，使用管理员核对的当前服务器指纹。

```text
node web/setup-release.js SSH用户名 私钥绝对路径 已核验的ED25519指纹
```

设置命令校验指纹、保存本机连接配置并只读检查发布入口。加密私钥可先加载到系统 SSH agent。配置完成后，在网页刷新「远程部署」状态。test 发布仍受原有账号权限及 dev 验收条件约束。

## 远程更新

第一次换用支持更新的版本时，解压新版完整 ZIP，通过 start.cmd、start.command 或 node web/launch.js 启动。以后在「设置 → 网页版远程更新」填写可信发布方的 HTTPS manifest.json 地址，保存后点击「检查更新」，再点击「安装更新并重启」。可开启启动时自动检查，安装由使用者确认。

程序下载并核对每个文件的 SHA256，停止本机服务后替换程序文件并自动重启。新版本启动失败时恢复上一版。更新保留仓库配置、更新地址、SSH 设置和外部项目目录。当前存在克隆、同步或发布操作时，请待操作完成后安装。

发布者运行 node web/package-web.js 输出路径.zip，会同时生成 输出路径-update 目录。将这个目录完整上传到支持 HTTPS 的静态文件服务器，把该目录内 manifest.json 的公开地址发给同事。服务器应对清单禁用缓存，先上传 files 文件，最后发布 manifest.json。更新文件与清单需要位于同一站点，下载地址须直接返回文件。

打包时可通过 SIMPLE_GITHUB_WEB_UPDATE_URL 环境变量预设团队更新清单地址。后续版本沿用同一清单地址发布，并在 web/update.js 提升 WEB_VERSION。发布目录应使用访问者有权限直接下载的地址。
